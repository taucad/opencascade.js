---
title: Extend with C++
description: Add file-backed C++ implementations or raw Embind registrations to a custom build.
---

Custom builds accept two file-backed extension mechanisms. Paths are relative
to the YAML file, read as UTF-8, and concatenated in declaration order. Missing
or unreadable files fail validation before compilation.

## `additionalCppFiles` — generated bindings

Use `additionalCppFiles` for C++ classes that libcascade's bindgen should
inspect and expose with generated JavaScript and TypeScript bindings:

```yaml title="build-configs/custom.yml"
additionalCppFiles:
  - wrappers/fair-curve.cpp

mainBuild:
  name: custom
  bindings:
    - symbol: FairCurve
```

```cpp title="build-configs/wrappers/fair-curve.cpp"
#include <TopoDS_Shape.hxx>

class FairCurve {
public:
  TopoDS_Shape Build() const { /* ... */ }
};
```

The generator discovers classes, constructors, methods, enums, referenced
OCCT types, and `Handle<T>`/NCollection aliases from these files. Generated
declarations become part of the build's `.d.ts`.

## `additionalBindFiles` — raw Embind

Use per-build `additionalBindFiles` when you need Embind features the
generator does not emit, such as free functions, `value_object`, collection
registrations, or `allow_subclass`:

```yaml title="build-configs/custom.yml"
mainBuild:
  name: custom
  bindings:
    - symbol: gp_Pnt
  additionalBindFiles:
    - bindings/helpers.cpp
```

```cpp title="build-configs/bindings/helpers.cpp"
#include <Standard_Real.hxx>
#include <emscripten/bind.h>

Standard_Real addReals(Standard_Real a, Standard_Real b) { return a + b; }

EMSCRIPTEN_BINDINGS(custom_helpers) {
  emscripten::function("addReals", &addReals);
}
```

An `additionalBindFiles` source may contain both its helper implementation and
its `EMSCRIPTEN_BINDINGS(...)` block, as above. It compiles directly and skips
bindgen, so consumers own any TypeScript declaration for raw exports.

For example, keep the generated module contract and add only the manual
surface your application registered:

```typescript
import init, { type OpenCascadeInstance } from './custom.js';

type CustomInstance = OpenCascadeInstance & {
  addReals(a: number, b: number): number;
};

const oc = (await init()) as CustomInstance;
console.log(oc.addReals(1.5, 2.25));
```

`additionalBindFiles` belongs to `mainBuild` or an `extraBuilds` entry because
its registrations can differ by output. `additionalCppFiles` is top-level and
shared by every output in the YAML.

## Which one?

- Prefer `additionalCppFiles` for ordinary classes and generated types.
- Use `additionalBindFiles` only for a binding construct bindgen cannot emit.
- Do not list the same source under both keys.

Both file lists and their SHA-256 digests are recorded in the build manifest
and provenance sidecar, making file changes part of artifact identity.

## Validate and build

```bash
./build-wasm.sh validate build-configs/custom.yml
./build-wasm.sh link build-configs/custom.yml
```

See [YAML schema](../reference/yaml-schema) for the full contract and
[Derive a C++ class in JavaScript](./derive-cpp-class-in-js) for an
`allow_subclass` example.
